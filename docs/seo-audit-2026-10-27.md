# Technical SEO audit — 2026-10-27

Scope: `savethreadsvideos.com` (this repository). Evidence-based, minimal fixes only. No download/extraction logic, API contract, routes, copy, branding, legal text, DB schema or deployment topology was changed. Nothing was deployed.

Environment note: Search Console / Bing Webmaster were **not accessible** to the auditor, so crawl/index diagnostics (coverage, sitemap processing, rich results, Core Web Vitals field data) could not be verified from inside GSC. Everything below was verified against the live site (HTTP evidence) and locally against a production build (`npm run build` + `npx wrangler dev --local --var MEDIA_RESOLVER_PROVIDER:mock`).

## A. Confirmed defects and fixes

| # | Severity | Confirmed defect (evidence) | Fix |
|---|---|---|---|
| 1 | Critical | **Soft 404s / SPA fallback.** Browser navigations (`Sec-Fetch-Mode: navigate`) to `/faq`, `/privacy`, `/blog`, `/threads-photo-downloader` and to a nonexistent path all returned **HTTP 200** with the homepage shell. Static Assets used the default SPA fallback and served the built `index.html` for every unknown path, so unique page HTML, canonicals and titles never reached crawlers on navigation. | `wrangler.jsonc`: `assets.binding: "ASSETS"`, `not_found_handling: "none"`, `run_worker_first: ["/"]`. All non-asset paths now reach the Worker (real 404s, SSR for every public route); hashed `/assets/*` still come straight from the edge. |
| 2 | Critical | **Canonical host mismatch.** Live `www.savethreadsvideos.com` 301-redirects to the apex, but `SITE_URL`, every `rel=canonical`, `og:url`, `/sitemap.xml` and `/robots.txt` used `www`. Every indexed URL would point at a redirecting host. | Apex `https://savethreadsvideos.com` everywhere: `wrangler.jsonc` `SITE_URL`, `.env.example`, `index.html`, `src/lib/site.ts`, `scripts/gen-static-seo.mjs`, tests. |
| 3 | High | **Homepage HTML was not crawlable.** `/` was served as the bare built shell: no `<header>`/`<nav>`, no footer, no WebSite JSON-LD, no security headers. | `run_worker_first: ["/"]` + `injectRoot()` in `src/server/content/render.ts` (balanced-`<div>` scanner; the built `index.html` contains fallback markup inside `#root`, so naive replacement corrupted the document). Homepage now server-renders site header/footer, nav links, disclaimer and `WebSite` JSON-LD. |
| 4 | High | **FAQ answers were client-only.** `/faq` raw HTML had the H1 but no Q&A text and no `FAQPage` JSON-LD. | Server-rendered Q&A (`<h3>` + answer paragraphs, from shared `src/lib/faq.ts`) plus `FAQPage` JSON-LD. React hydration still takes over the accordion. |
| 5 | High | **Per-page metadata was missing/wrong on SPA routes.** Canonical, description, `og:type`, `og:locale` were static or homepage-derived on tool/guide pages. | `applyPageSeo()` in `src/lib/site.ts`; wired in `src/pages/pages.tsx` and `src/pages/dynamic.tsx`; server side adds `og:type` (`website` vs `article`) and `og:locale` (`en_US`/`fr_FR`/`ar_AR`). |
| 6 | Medium | **`og:image` was SVG.** Major social platforms do not render SVG previews — links shared without a preview image. | Added `public/og-image.png` (1200×630 PNG, 33 KB, generated from the existing SVG) and `og:image:width/height/alt`, `twitter:image:alt`. |
| 7 | Medium | **CSP blocked the anti-FOUC inline theme script.** Console CSP violations on every page; theme flashed wrong on first paint for dark-mode users. | Stable `sha256` hash in `src/lib/csp.ts`, included by both CSP builders. Hash (not nonce) keeps responses cacheable. A test recomputes the hash from `index.html` and fails on drift. |
| 8 | Medium | **`/admin*` would 404** once SPA fallback was removed (no static files exist for those routes). | Explicit Worker `adminShell` for `/admin` and `/admin/*`, with `X-Robots-Tag: noindex, nofollow` and `cache-control: no-store`. |
| 9 | Medium | **Sitemap `<loc>` not URL-encoded and duplicates possible.** Arabic slugs were emitted raw; DB and static routes could repeat. | `encodePath()` (Worker) and `encodeLoc()` (build script) percent-encode only non-ASCII segments, ASCII paths stay byte-identical; dedupe with DB slugs first. |
| 10 | Low | **`HEAD` returned 404** on all SEO/public-content routes. | `handleStaticSeo` and `handlePublicContent` support `HEAD` with identical status/headers and empty body. |
| 11 | Low | **API JSON headers inconsistent** — `/api/content/*`, `/api/tracking.json`, `/api/ads.json` did not share the `noindex, nofollow` public JSON policy. | Shared `publicJsonHeaders` helper. |
| 12 | Medium (regression, found in post-fix verification) | **`npm run dev` hydration broke** after the Worker started serving `/`: the production CSP header reached Vite's dev server and blocked Vite's own inline React Refresh preamble, so `@vitejs/plugin-react` aborted ("can't detect preamble") and the page rendered as unstyled SSR text (no CSS, no form). | `cspHeaderValue()` in `src/lib/csp.ts` is now production-only (`import.meta.env.DEV` → no CSP). `wrangler dev` runs the production build and still receives/verifies the real CSP. Tests cover both branches. |

Non-defects checked and left alone: trailing-slash `308` canonicalization, `X-Robots-Tag: noindex` on admin/API JSON, Googlebot-vs-browser content parity (no cloaking), Arabic UTF-8 slugs, route ordering, hreflang absence (single-language content per URL is correct — no fake hreflang), and the sitemap's `lastmod` values (derived from real DB `updated_at`, none fabricated).

## C. Verification performed

- `npm test` → **157 tests / 16 files pass**.
- `npm run build` → **passes** (strict `tsc`, Vite SSR + client, static SEO). Sitemap: **50 URLs** (8 static entries incl. `/` and `/blog` + 23 DB tool pages + 19 DB guides), **42 `<lastmod>`** (DB entries only), apex only, **0** duplicates, **0** raw non-ASCII characters (Arabic percent-encoded).
- `npx wrangler dev --port 8788 --local --var MEDIA_RESOLVER_PROVIDER:mock`, browser-style headers:
  - 10/10 `SEO_ROUTES` → 200, exactly 1 `<h1>`, unique titles and H1s, canonical on the apex, `og:type=website`, `og:image=/og-image.png`.
  - Homepage → crawlable `<nav>` ×2, `<footer>`, WebSite JSON-LD, canonical `https://savethreadsvideos.com/`.
  - `/faq` → answers + FAQPage JSON-LD in raw HTML; canonical `https://savethreadsvideos.com/faq`.
  - Unknown path → **404** branded page, no shell. `/faq/` → 308. `/index.html` → 307 `/`.
  - `/admin`, `/admin/login`, `/admin/settings` → 200, `X-Robots-Tag: noindex, nofollow`, `no-store`.
  - `/sitemap.xml` → 200 XML (50 locs, apex, encoded); `/robots.txt` → `Allow: /`, `Disallow: /api/`, `Disallow: /admin/`, `Sitemap:` apex; `/og-image.png` → 200 `image/png`; `/favicon.svg` → 200.
  - `HEAD` → 200 on `/`, `/faq`, `/privacy`, `/terms`, `/contact`, `/blog`, `/threads-video-downloader`, `/how-to-download-threads-videos`; 404 on unknown.
  - API: `/api/health` → `{"ok":true,"resolver":"mock"}`; mock video/photo/carousel resolve correctly (carousel = 5 items with tokens); `private` → 403 `PRIVATE_CONTENT`; `empty` → 404 `MEDIA_NOT_FOUND`; `javascript:` and SSRF metadata host → 400 `INVALID_URL`; external domain → 400 `UNSUPPORTED_URL`; forged download token → 404; all API JSON `noindex, nofollow`.
  - Browser (hydrated): `/faq` hydrates with 1 H1 + header/footer; homepage form resolves a carousel → "5 media files found", 4 images + 1 video, per-item Download, MP3, Download All, New Download; no console CSP errors.
- `npm run dev` (Vite dev on :5173) after the CSP split: homepage and `/faq` render styled, form + language selector + theme toggle present, **0 console errors**, CSP header absent as intended (Vite preamble runs).
- `npx wrangler dev --local` (production build) after the same change: CSP header **present** and the page hydrates (`form`, theme toggle) with no console errors — i.e. the dev exception did not weaken production.
- Googlebot UA returned byte-identical content to a normal browser on the audited routes (no cloaking).

Not verifiable here: Search Console coverage/rich results, Bing index state, DB-backed pages (`/api/content/*`, tool/guide slugs) — the local generated config has `d1_databases: []` and production uses Supabase. Those pages are server-rendered by the same code path that was exercised for static routes and are generated from the same `render.ts` templates.

- Or revert only the routing regression by restoring the previous `assets` block (SPA fallback) — **not recommended**: it re-introduces the soft-404s.
- Deployment rollback: `npx wrangler rollback` (or the Cloudflare dashboard's deployment history).

## F. Out-of-scope findings (reported, not changed)

1. `how-to-download-instagram-reels-web-tool` is a DB tool page for a **different product** and is listed in the sitemap. Content decision for the owner (removing it would change routes/content, which this audit must not do).
2. Guide `Article` JSON-LD has no `author`/`datePublished`. Fixing it would require inventing data, which is disallowed; add real author/date fields in the CMS when available.
3. `/api/tracking.json` `head_custom` contains a full HTML document used as a "Bing verification" value — likely a mis-paste from `<meta name="msvalidate.01">` or a verification file. Admin data, not code; harmless but should be corrected in `/admin/seo-webmaster`.
4. `canonical_base` (tracking setting) can override canonicals site-wide if an admin sets it. It is empty in production today; it is an admin-controlled escape hatch, not a bug.
5. Rate limiting is per-isolate in memory; the documented production layer remains a Cloudflare rate-limiting rule.
6. Static `dist/client/sitemap.xml`/`robots.txt` shadow the Worker routes for navigations. The build-time fetch of live slugs keeps the sitemap accurate, but new DB pages are only in the served sitemap after the next `npm run build`.

## G. Interpretation for the owner

The two defects that mattered most for indexing were (1) the SPA fallback that made every URL return the homepage with 200 and (2) the `www` canonical mismatch. Both are fixed and verified. Everything else improves how already-indexed pages are rendered and previewed (per-page metadata, PNG social image, FAQ markup, real 404s, admin noindex) rather than changing the site's content surface.
